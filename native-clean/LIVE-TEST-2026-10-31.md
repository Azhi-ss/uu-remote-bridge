# SK live interoperability test — 2026-10-31

Target: the user's SK Windows machine, with its existing official UU host.
Controller: native-clean CLI on macOS; no GUI automation was used to send
remote commands or input. The official local app was disconnected during tests.

## Results

- Room authentication, signaling and WebRTC: connected; all five data channels opened.
- Desktop: H.264 received and decoded at 2816 × 1760; full-resolution PPM snapshots inspected.
- ANSI viewer: an 8-second process run rendered 47 frames, decoded 137 of 140
  received access units (padding/decoder buffering accounts for non-image units),
  and reported zero decoder errors. The final release run rendered 46 frames in
  8 seconds and decoded 140 of 143 units; one startup reference-frame error
  recovered after a keyframe. Ctrl-C returned exit 0 and restored the terminal.
  This is a terminal preview, not a 30/60 FPS GUI.
- Keyboard: Windows virtual-key events opened Win+R; text input produced
  `UU_VIEWER_INPUT_OK` in the Run dialog, verified in a returned frame.
- Mouse: normalized absolute move and button press/release clicked the Run
  input field and later Cancel. A subsequent snapshot confirmed the dialog closed.
- File round trips: 98,441 bytes and 1,048,713 bytes of random data uploaded
  and downloaded; source/returned SHA-256 hashes matched in both cases.
- The 1,048,713-byte upload took 1.41 s and download 1.20 s in this run,
  including connection setup. These timings are observations, not guarantees.
- Test file removal was checked by listing the remote directory. Test input
  was cancelled; no command from the Run dialog was executed.

## Interoperability fixes found by these tests

- Parse simultaneous `signaling_server` and `signaling_list` fields.
- Use `app_control_id`, TURN Password credentials, nested SOAC data and session routing.
- Register H.264/Opus codecs, request the video track, negotiate desktop capabilities,
  answer the host's Echo request and request keyframes.
- Accept two-byte H.264 AUD NAL units and RTP padding instead of losing their
  whole reference frame. Buffer large fragmented keyframes, but abandon missing
  packets after 500 ms so an incomplete first frame cannot stall the viewer.
- Route official file replies from TEXT/CONTROL; accept >64 KiB SCTP blocks.
- Treat omitted zero block numbers as zero and use compatible task identifiers.
- Close the WebRTC peer and signaling session on normal CLI completion.

## Scope

This test verifies the CLI viewer against this official Windows host. It does
not prove every OS capture backend, monitor arrangement, video codec, very
large transfer, resume scenario or directory edge case. Audio playback,
clipboard synchronization, and automatic local-terminal key forwarding are
not implemented by the terminal preview. Credentials and desktop screenshots
are not included in the repository.
